# Grimorio — Agent Context

Compact guidance for AI agents working in this repo. Every line answers: "Would an agent likely miss this without help?"

## Build & Test

```bash
# Run all tests (excludes cmd/ packages)
go test -v -race -coverprofile=coverage.out $(go list ./... | grep -v '/cmd/')

# Coverage gate: 60% minimum
make coverage

# Lint
golangci-lint run --timeout=5m ./...

# Build binary
make build
# Or directly:
go build -ldflags "-s -w -X main.version=dev -X main.commit=abc123 -X main.date=..." -o grimorio ./cmd/grimorio
```

## Architecture

- **Entrypoint**: `cmd/grimorio/main.go` — MCP server over stdio
- **Core packages**:
  - `internal/compiler/` — Markdown → HTML → PDF (the engine you are replacing)
  - `internal/services/` — Business logic (Campaign, SessionPrep, etc.)
  - `internal/mcp/handlers/` — MCP tool handlers
  - `internal/domain/` — Domain models
  - `internal/repository/` — Filesystem persistence
- **Agent prompts**: `agents/` — Filesystem source of truth for AI agent instructions
- **Skills**: `skills/` — Domain-specific skill definitions (WotC format, etc.)

## PDF Compiler — Critical Context

**The old engine (`wkhtmltopdf`) is deprecated and broken on CachyOS/Arch.**

**New behavior** (auto-detect, multi-engine):
- `internal/compiler/compiler.go` detects available engines in priority order:
  1. `chromium` (preferred)
  2. `chrome`
  3. `google-chrome`
  4. `google-chrome-stable`
  5. `wkhtmltopdf` (legacy fallback)
- Pass `pdfEngine: ""` (empty string) to `compiler.New()` for auto-detection
- `htmlToPDF()` branches on `isChromiumEngine()` — Chromium uses `--headless --print-to-pdf`, wkhtmltopdf uses legacy flags
- SVG images are embedded as relative paths for both engines (no base64 needed for SVG)

**Tests skip if no PDF engine is available**: Use `compiler.IsPDFEngineAvailable()` to gate integration tests.

## Key Conventions

- **Go version**: 1.24+ (uses generics, `slices` package, etc.)
- **Testing**: Table-driven tests preferred. Mock repositories via interfaces.
- **Error handling**: Wrap with `fmt.Errorf("...: %w", err)` consistently
- **Markdown processing**: Custom parser in `compiler.go` (not a library). Supports:
  - WotC-style CSS classes (`.dm-sidebar`, `.stat-block-v2`, etc.)
  - Scene placeholders `[SCENE: ...]`
  - Code asset refs `` `assets/file.png` ``
  - Auto-closing unclosed `<div>` tags
- **i18n**: Bilingual (English/Spanish) in docs and some templates

## MCP Server Context

- Communicates via stdio (JSON-RPC)
- Tools are defined in `internal/mcp/handlers/`
- The `grimorio` command in OpenCode maps to the MCP server
- `.mcp.json` is auto-generated by `install.sh`/`install.ps1`

## Common Pitfalls

- **Do NOT hardcode `wkhtmltopdf`** as the PDF engine in new code. Use `""` for auto-detect or test with specific engines.
- **Do NOT commit `install.sh` changes without testing** — it's POSIX sh, not bash. Avoid bashisms.
- **Templates are embedded** via `//go:embed` in `internal/compiler/templates/`. Edit `.tmpl` files, not Go code, for format changes.
- **Binary name**: `grimorio` (Linux/macOS), `grimorio.exe` (Windows)
- **Campaign directory**: `~/campaigns/<campaign-name>/`
